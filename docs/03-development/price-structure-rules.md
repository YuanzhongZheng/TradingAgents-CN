# 价格结构计算口径

## 缠论线段

实现：`core/tools/implementations/technical/chanlun_segments.py`。

以现有包含处理、分型和笔端点为输入，采用[缠中说禅第67课](https://blog.sina.com.cn/s/blog_486e105c01000c16.html)的特征序列口径：上涨段取下降笔，下降段取上涨笔，对包含元素作方向性合并。合并保留高低极值各自的原始端点索引。

- 至少三笔且起始三笔有重叠，才建立线段候选。
- 标准特征序列出现对应分型，第一、第二元素无缺口时确认结束。
- 存在缺口时，必须再出现反向特征序列的分型；第二序列不再递归检查缺口。确认前原方向出现更极端端点时，旧候选失效。
- 最后一个可能被同类分型替换的笔端点不能作为确认依据。结果分别提供端点时间、确认时间、构成笔数和确认规则。完整 K 线入口将确认时间推进到支持分型的右侧 K 线。
- 按输入前缀确认，追加笔不会重画已确认线段。样本之前的起点不做推断。

报告同时保留三笔重叠近似区间，并独立计算三条已确认线段的重叠区间；候选线段不参与后者。三线段重叠不自动等同于递归定义的高级别走势中枢。原来的力度/背驰观察仍是笔级别候选，不因增加线段字段而升级为确认背驰。

## 内部子浪

实现：`core/tools/implementations/technical/elliott_subwaves.py`。

使用父浪所在周期的原始 K 线，以父级 ZigZag 阈值的三分之一提取区间内更细摆动。父浪端点必须已经确认，内部两端必须与父浪端点对齐；不插入或强制制造子浪，区间外 K 线不参与计算。这是同周期、单层嵌套结构检验，不是加载更低时间周期或无限递归验证。

| 父形态 | 第一层子浪数量 | 价格检查 |
|---|---|---|
| 普通推动 | 5-3-5-3-5 | 各五子浪检查第2浪起点、第3浪突破及非最短、第4浪不重叠等规则；三子浪检查交替和净运动方向 |
| 之字形调整 | 5-3-5 | 五子浪价格规则及三子浪方向规则 |
| 平台形调整 | 3-3-5 | 三子浪方向规则及末段五子浪价格规则 |

模板依据：[普通推动](https://www.elliottwave.com/waveopedia/impulse/)、[之字形](https://www.elliottwave.com/waveopedia/zigzags/)、[平台形](https://www.elliottwave.com/waveopedia/flats/)。比例范围仍是经验提示，不代替子浪结构验证。

结果提供每个父浪的时间区间、期望/观察段数、阈值、子浪端点、逐条检查与失败原因：

- `passed`：所支持模板在本分辨率下的第一层检查通过，仍是波浪候选。
- `failed`：段数吻合，但支持模板的价格/方向规则不通过。
- `insufficient`：K线或可辨摆动不足，端点未对齐，或同根K线内顺序不明；不能说通过，也不据此断言不存在波浪。
- `unsupported`：更多子浪、未细分形态等不在当前模板内，不自动合并摆动凑数。
- `unavailable`：父端点在输入数据中无法定位。

更深层子浪、楔形、延长浪、三角形、组合调整及跨周期映射仍未覆盖。阈值变化会影响摆动分解，本实现固定阈值并公开输出，不搜索一个能通过的阈值。后续 ABC 如被外层识别，也单独报告检验状态。未确认末端只保留暂定计数，不纳入已确认父浪的内部验证。

## 行情快照、缓存与时间预算

市场分析师每次 `execute` 创建独立的行情快照；线程任务显式复制 ContextVar，退出分析后复位。同次分析共用一个适配器管理器，日线结构与普通行情/技术指标报告都经过 `read_historical_bars`。首次日线读取涵盖 465 个自然日（配置回溯更长时取更长区间），之后只裁剪副本，不再换源重取。股票后缀和日期格式会归一化，复权统一为 `qfq`。周线、分钟线保留各自的真实周期，不从日线冒充分钟线。

日线冻结前检查缓存截止日期，落后时按优先级读取适配器并写回；刷新失败时保留带实际日期的缓存数据。周末按前一个工作日检查，法定节假日可能多尝试一次刷新。分析中的行情工具不再另起 JIT 同步改变已经使用的日线。独立调用行情工具保留原有 JIT 行为。这里保证的是同次分析对同一周期的重复读取一致，不代表四个外部数据源能提供交易所意义上的同一时刻快照，也不改变历史前复权数据的既有定义。

`core/market_runtime` 提供统一的线程安全 TTL/LRU 缓存和在途请求合并：

- 普通行情报告最多 64 项，结构结果按单周期最多 256 项，管理器日线最多 128 项；共享结果 TTL 为 180 秒。分析内冻结的数据存续到分析结束，最多 64 项。
- 相同请求在线程分配前合并，成功、异常、池满后的在途记录都会清理。清空缓存会提升代次，旧请求完成后不能重新填回新缓存。
- 返回副本，调用方修改结果不会污染后续请求。结构错误、无行情、普通行情失败文本不作为成功结果缓存；快照内的空日线保留为空，避免同次分析悄悄换数据。
- 缓存区分数据源配置、来源上下文、日期、周期和复权。配置保存后使配置缓存失效；管理器在配置变化或五分钟后更新，进行中的分析继续使用原管理器。多进程部署的其他进程仍依赖配置 TTL 刷新。

结构取数与统一行情工具共用最多 8 个工作线程，不建立无界等待队列。默认总等待预算 20 秒，HTTP 单次连接/读取上限 8 秒，且每次 HTTP 请求受剩余预算约束。Tushare 使用私有客户端，AKShare 使用私有函数上下文传递 HTTP 超时，均不修改全局 requests 或共享 SDK 客户端。可通过 `.env` 的 `MARKET_STRUCTURE_TIMEOUT_SECONDS`、`MARKET_PROVIDER_TIMEOUT_SECONDS` 调整。

某周期超时或线程池已满时只将该周期标为不可用，保留其他周期结果。等待超时不会取消其他调用者共用的请求。QMT、BaoStock 的共享 K 线读路径现在使用下面的进程隔离；本地数据库、其他 HTTP SDK 仍受各自驱动超时和外层等待预算限制，不能声称所有外部调用都已可强制取消。

`tests/unit/test_market_runtime.py` 覆盖并发合并、等待超时、容量/TTL、异常清理、配置隔离、旧请求与清缓存竞态、线程上下文、日线一次读取和部分成功。相关验证不访问真实行情源。


## QMT / BaoStock 进程隔离

`get_kline_with_fallback` 将这两个源的可用性探测、连接和 K 线读取放入独立进程，其他源继续原有路径。每个后端进程最多保留三个工作进程：QMT 读取、BaoStock 读取、QMT 历史下载。均延迟启动，空闲 120 秒退出；冷启动和排队计入预算。行情进程串行执行，一项运行、最多四项等待；队列满时快速降级。

父进程在截止时间前预留最多 0.5 秒回收时间，先 terminate，再 kill，并 wait 确认退出；确认前不会创建替代进程。若操作系统仍不能回收，保留句柄并暂停该源，避免增加进程数量。连续两次执行失败后暂停 30 秒，再允许一个串行恢复探测。超时、崩溃和协议错误会销毁整代通信目录；旧结果不能进入新请求。队列超时不终止别人的在途请求。

通信使用权限受限的临时目录与原子替换的 JSON 文件，避免读取进程被杀时留下的半截管道消息。请求有唯一编号和截止时间，消息最多 8 MiB；父进程校验编号、价格字段和请求日期后才走现有缓存/数据库写回。子进程不写应用缓存、不连接交易账户、不发送交易指令，终止对象只来自本服务创建的 Popen 句柄，不按进程名关闭 QMT 终端。

BaoStock 的 socket 默认超时仅在它自己的子进程内设置，不修改主服务的 socket。QMT 行情读取显式关闭同步下载，并复用已经运行的 QMT 服务；工作进程禁止启动本地 QMT 服务。启用 `QMT_AUTO_DOWNLOAD_HISTORY` 时，读取后异步提交下载，最多一项运行、八项排队，重复任务合并，成功后五分钟内不重复。下载使用自己的进程和 `MARKET_QMT_DOWNLOAD_TIMEOUT_SECONDS`（默认 60 秒），不会占用行情线程池。下载成果供后续分析使用，当前分析仍使用冻结的快照；首次本地无数据时会尝试其他行情源。

应用生命周期结束和正常解释器退出都会请求停止后台下载、回收工作进程。配置改变会重建相应 SDK 进程。以上限制按后端进程计数，多 worker 部署需乘以 worker 数量。直接调用适配器的其他接口（如同步股票列表、持仓导入）不在本次 K 线隔离范围内。终止客户端也不保证撤销 QMT 服务已经接受的后台下载。

`tests/unit/test_market_process_isolation.py` 使用真实 OS 子进程验证忽略 SIGTERM 的永久阻塞、连续回收与恢复、崩溃、过期响应、有界排队、熔断、配置切换和退出清理；另通过假 BaoStock SDK 验证生产子进程入口。测试不连接真实 QMT 终端或真实行情服务。

## 工具按需加载与线段增量计算

`core.tools`、`implementations` 及分类包使用延迟导出，原有 `from ... import ...` 接口继续可用。直接导入 `chanlun`、`elliott_wave`、`chanlun_segments` 等纯算法不会构造工具注册表，也不会加载 pandas、LangChain 或行情 SDK。算法与工具注册的依赖边界通过独立 Python 进程测试。

`ToolRegistry()` 仅复制内置元数据；`get`、`get_function`、`get_by_ids`、`get_langchain_tool` 按工具 ID 导入对应模块，再取得装饰器补全后的参数与实现。多个工具同属一个模块时一并注册。`list_all` 及类别/在线筛选仍执行一次完整发现，保留 Legacy Bridge、助手操作和动态扩展；分析 Worker 启动时显式预热完整目录，因此这项优化不等于完整服务启动速度提升同样倍数。

`core/tools/_tool_index.py` 只存工具 ID 到模块的映射，不复制描述或参数 schema；由 `scripts/generate_tool_index.py` 静态读取装饰器生成，支持无源码的 pyc 部署。新增或移动工具后运行：

```sh
env/bin/python scripts/generate_tool_index.py
env/bin/python scripts/generate_tool_index.py --check
```

线段划分逐个接收稳定端点，维护标准特征序列、末尾分型和起点以来的极值；包含合并只重新检查受影响的末尾三元组。缺口候选分别维护反向序列，候选失效后释放其状态。保留逐前缀的确认顺序、三笔重叠检查、末笔确认延迟与端点原始位置。此处是单次计算内部的增量更新，不是在不同请求之间持久化未确认线段，也不新增缠论规则。

冻结的优化前算法位于 `tests/fixtures/chanlun_segments_reference.py`，仅供测试与基准使用。`test_chanlun_incremental.py` 比较固定种子的随机走势、上下行对称走势的每个前缀，并覆盖等价价格、包含合并及长期趋势的价格读取次数。不存在不依赖数据形态的线性复杂度承诺：多个缺口反向候选及相邻线段重叠观察区间仍可能重复处理部分端点。

可复现合成基准：

```sh
USE_MONGODB_STORAGE=false env/bin/python scripts/benchmark_structure_runtime.py
USE_MONGODB_STORAGE=false env/bin/python -m pytest tests/unit/test_tool_lazy_loading.py tests/unit/test_chanlun_incremental.py tests/unit/test_chanlun_segments.py -q
```

2026-10-20 本机 Python 3.10 测得：纯算法导入改动前单次约 3.63 秒，改动后三次中位数约 8.6 毫秒；趋势数据 1,000 个端点由 273.67 毫秒降至 1.32 毫秒，2,000 个端点由 1,117.97 毫秒降至 2.65 毫秒（算法均为三次中位数）。这些数字只衡量模块导入和合成数据计算，不包含真实行情网络耗时或 LLM 分析耗时。
