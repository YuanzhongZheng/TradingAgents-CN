# 价格结构计算口径

## 缠论线段

实现：`core/tools/implementations/technical/chanlun_segments.py`。

以现有包含处理、分型和笔端点为输入，采用[缠中说禅第67课](https://blog.sina.com.cn/s/blog_486e105c01000c16.html)的特征序列口径：上涨段取下降笔，下降段取上涨笔，对包含元素作方向性合并。合并保留高低极值各自的原始端点索引。

- 至少三笔且起始三笔有重叠，才建立线段候选。
- 标准特征序列出现对应分型，第一、第二元素无缺口时确认结束。
- 存在缺口时，必须再出现反向特征序列的分型；第二序列不再递归检查缺口。确认前原方向出现更极端端点时，旧候选失效。
- 最后一个可能被同类分型替换的笔端点不能作为确认依据。结果分别提供端点时间、确认时间、构成笔数和确认规则。完整 K 线入口将确认时间推进到支持分型的右侧 K 线。
- 按输入前缀确认，追加笔不会重画已确认线段。样本之前的起点不做推断。

报告同时保留三笔重叠近似区间，并独立计算三条已确认线段的重叠区间；候选线段不参与后者。三线段重叠不自动等同于递归定义的高级别走势中枢。原来的力度/背驰观察仍是笔级别候选，不因增加线段字段而升级为确认背驰。

## 内部子浪

实现：`core/tools/implementations/technical/elliott_subwaves.py`。

使用父浪所在周期的原始 K 线，以父级 ZigZag 阈值的三分之一提取区间内更细摆动。父浪端点必须已经确认，内部两端必须与父浪端点对齐；不插入或强制制造子浪，区间外 K 线不参与计算。这是同周期、单层嵌套结构检验，不是加载更低时间周期或无限递归验证。

| 父形态 | 第一层子浪数量 | 价格检查 |
|---|---|---|
| 普通推动 | 5-3-5-3-5 | 各五子浪检查第2浪起点、第3浪突破及非最短、第4浪不重叠等规则；三子浪检查交替和净运动方向 |
| 之字形调整 | 5-3-5 | 五子浪价格规则及三子浪方向规则 |
| 平台形调整 | 3-3-5 | 三子浪方向规则及末段五子浪价格规则 |

模板依据：[普通推动](https://www.elliottwave.com/waveopedia/impulse/)、[之字形](https://www.elliottwave.com/waveopedia/zigzags/)、[平台形](https://www.elliottwave.com/waveopedia/flats/)。比例范围仍是经验提示，不代替子浪结构验证。

结果提供每个父浪的时间区间、期望/观察段数、阈值、子浪端点、逐条检查与失败原因：

- `passed`：所支持模板在本分辨率下的第一层检查通过，仍是波浪候选。
- `failed`：段数吻合，但支持模板的价格/方向规则不通过。
- `insufficient`：K线或可辨摆动不足，端点未对齐，或同根K线内顺序不明；不能说通过，也不据此断言不存在波浪。
- `unsupported`：更多子浪、未细分形态等不在当前模板内，不自动合并摆动凑数。
- `unavailable`：父端点在输入数据中无法定位。

更深层子浪、楔形、延长浪、三角形、组合调整及跨周期映射仍未覆盖。阈值变化会影响摆动分解，本实现固定阈值并公开输出，不搜索一个能通过的阈值。后续 ABC 如被外层识别，也单独报告检验状态。未确认末端只保留暂定计数，不纳入已确认父浪的内部验证。


## 行情快照、缓存与时间预算

市场分析师每次 `execute` 创建独立的行情快照；线程任务显式复制 ContextVar，退出分析后复位。同次分析共用一个适配器管理器，日线结构与普通行情/技术指标报告都经过 `read_historical_bars`。首次日线读取涵盖 465 个自然日（配置回溯更长时取更长区间），之后只裁剪副本，不再换源重取。股票后缀和日期格式会归一化，复权统一为 `qfq`。周线、分钟线保留各自的真实周期，不从日线冒充分钟线。

日线冻结前检查缓存截止日期，落后时按优先级读取适配器并写回；刷新失败时保留带实际日期的缓存数据。周末按前一个工作日检查，法定节假日可能多尝试一次刷新。分析中的行情工具不再另起 JIT 同步改变已经使用的日线。独立调用行情工具保留原有 JIT 行为。这里保证的是同次分析对同一周期的重复读取一致，不代表四个外部数据源能提供交易所意义上的同一时刻快照，也不改变历史前复权数据的既有定义。

`core/market_runtime` 提供统一的线程安全 TTL/LRU 缓存和在途请求合并：

- 普通行情报告最多 64 项，结构结果按单周期最多 256 项，管理器日线最多 128 项；共享结果 TTL 为 180 秒。分析内冻结的数据存续到分析结束，最多 64 项。
- 相同请求在线程分配前合并，成功、异常、池满后的在途记录都会清理。清空缓存会提升代次，旧请求完成后不能重新填回新缓存。
- 返回副本，调用方修改结果不会污染后续请求。结构错误、无行情、普通行情失败文本不作为成功结果缓存；快照内的空日线保留为空，避免同次分析悄悄换数据。
- 缓存区分数据源配置、来源上下文、日期、周期和复权。配置保存后使配置缓存失效；管理器在配置变化或五分钟后更新，进行中的分析继续使用原管理器。多进程部署的其他进程仍依赖配置 TTL 刷新。

结构取数与统一行情工具共用最多 8 个工作线程，不建立无界等待队列。默认总等待预算 20 秒，HTTP 单次连接/读取上限 8 秒，且每次 HTTP 请求受剩余预算约束。Tushare 使用私有客户端，AKShare 使用私有函数上下文传递 HTTP 超时，均不修改全局 requests 或共享 SDK 客户端。可通过 `.env` 的 `MARKET_STRUCTURE_TIMEOUT_SECONDS`、`MARKET_PROVIDER_TIMEOUT_SECONDS` 调整。

某周期超时或线程池已满时只将该周期标为不可用，保留其他周期结果。等待超时不会取消其他调用者共用的请求，也不会谎称正在执行的线程已经退出。BaoStock、QMT、本地数据库等不支持这里的 HTTP 超时注入；若其底层调用长时间不返回，线程槽位会一直占用，耗尽时新请求快速返回繁忙。HTTP 的连接/读取超时也不等价于强制杀死线程，因此调用方总等待预算另行控制。该限制需要后续进程隔离才能彻底消除。

`tests/unit/test_market_runtime.py` 覆盖并发合并、等待超时、容量/TTL、异常清理、配置隔离、旧请求与清缓存竞态、线程上下文、日线一次读取和部分成功。相关验证不访问真实行情源。
